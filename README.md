## Протокол

Глобальное временное разбиение по UTC, без случайного перемешивания:

| Часть | Время | Событий |
|---|---|---:|
| Train | До 2016-01-01 | 330 951 |
| Validation | 2016-01-01 ≤ t < 2017-01-01 | 72 730 |
| Test | t ≥ 2017-01-01 | 49 308 |
| Финальный fit | Train + validation | 403 681 |

История заморожена на начало holdout-окна: запрос validation — 2016-01-01,
запрос test — 2017-01-01. История не обновляется событиями окна.
Релевантность бинарная: **rating ≥ 4**. Для каждого пользователя ранжируется
**весь каталог fit за вычетом всех просмотренных в fit товаров**, включая оценки 1–3;
отрицательные кандидаты при оценке не сэмплируются. При равных scores порядок по ASIN.

Основная когорта: известные в fit пользователи с хотя бы одним доступным
релевантным holdout-товаром и ≥10 кандидатами. Cold-start и пользователи без
релевантности исключены из основных метрик, их число и покрытие показаны отдельно.
Когорта, кандидаты и relevance одинаковы для всех моделей, независимо от objective.
Если персонализация недоступна или кандидат имеет нечисловой score, **вся** выдача
пользователя заменяется популярностью положительных fit-событий; пользователь сохраняется.

Основная метрика выбора заранее зафиксирована: **macro NDCG@10** — учитывает позицию
релевантных товаров. **Macro Recall@10** измеряет долю найденных релевантных товаров.
Дополнительно: покрытие каталога, fallback, срезы истории 1–4 / 5–9 / 10+ и head/tail
популярности. Формулы и детали — в notebook и `evaluation.py`.

Validation: 10 207 пользователей, 15 578 товаров, 25 646 релевантных событий.
Test: 9 521 пользователь, 16 721 товар, 23 454 релевантных события.
Последняя когорта покрывает **57,95%** положительных test-событий, поэтому результаты
не характеризуют весь поток новых пользователей и товаров.
Протокол: [reports/evaluation_protocol.json](reports/evaluation_protocol.json).

## Модели и итоговое качество

Каждая модель содержит собственные обучение, score и recommendation.
Используются NumPy/SciPy; готовых рекомендательных моделей и готовых обучателей нет.

- **ItemKNN:** cosine по бинарным положительным событиям, shrinkage по числу
  общих пользователей, top-neighbors для каждого целевого товара.
- **iALS:** implicit weighted squared error; p=1 для rating≥4, c=1+αp,
  ненаблюдаемые пары имеют p=0, c=1. Точные ALS-обновления с L2-регуляризацией.
- **EASE:** min ||X−XB||² + λ||B||² при diag(B)=0, точное ridge-решение.
  Сохраняются отрицательные веса. [Steck, 2019](https://arxiv.org/abs/1905.03375).
- **FM:** полная двухфакторная FM по user/item ID, бренду и категориям.
  BCE, собственный AdaGrad, observed rating 1–3 как negative и два случайных
  unseen negative на positive. Сэмплирование только по fit; оно не меняет кандидатов оценки.
- **timeSVD++:** исходные рейтинги и MSE; implicit history всех fit-оценок,
  временные item bias, user bias и дрейф факторов, локальные user-day эффекты.
  Собственный полный градиент и AdaGrad; будущие неизвестные user-day эффекты равны нулю,
  будущий bin ограничивается последним fit-bin.
  [Koren, 2009, уравнение 14](https://cseweb.ucsd.edu/classes/fa17/cse291-b/reading/p447-koren.pdf).

Настройки выбраны только по validation NDCG@10. Затем все модели обучены заново,
без warm start. Для seed используется 42; отдельные seeds sampling/shuffle указаны в JSON.

| Модель | Выбранные настройки | Val NDCG@10 | Test NDCG@10 | Test Recall@10 |
|---|---|---:|---:|---:|
| Popularity, контроль | Число положительных fit-событий | 0.005779 | 0.009712 | 0.012274 |
| ItemKNN | 100 соседей, shrinkage=10 | 0.021111 | 0.021241 | 0.032328 |
| iALS | factors=64, α=40, λ=0.1, 15 итераций | 0.021893 | **0.022217** | **0.034842** |
| EASE | λ=100 | **0.023372** | 0.022048 | 0.033390 |
| FM | factors=32, LR=0.05, λ=0.001, 12 эпох | 0.008494 | 0.009612 | 0.016354 |
| timeSVD++ | factors=32, bins=36, λ=0.01, LR=0.05, 50 шагов, β=0.4 | 0.000616 | 0.000579 | 0.001113 |

Reference-модель, выбранная до test, — **EASE**. На test точечно лидирует iALS,
но парный 95% bootstrap-интервал NDCG-разности iALS−EASE
**[−0.001465; 0.001961]** включает ноль. Доказанного превосходства iALS над EASE нет.
Bootstrap: 2 000 выборок пользователей, seed=42; интервалы не скорректированы
за множественные сравнения и не учитывают seed-вариацию обучения.

Метаданные улучшают FM при одинаковых выбранных настройках: validation NDCG
0.008494 против 0.005990 у ID-only. Эта ablation не настраивалась отдельно.
Временная часть timeSVD++ здесь не улучшила результат: static SVD++ даёт validation
NDCG 0.001193. Низкий train RMSE не означает хорошее ранжирование;
74,77% train user-day пар содержат единственный рейтинг, а на будущем дне локальные
эффекты неизвестны. Эти наблюдения не доказывают единственную причину слабого качества.

ItemKNN имеет наибольший test Recall хвоста: 0.013090 против 0.009704 у EASE
и 0.002494 у iALS. Выбор зависит также от охвата и популярности товаров.
После открытия test не менялись targets, признаки, число шагов, параметры и протокол.

## Запуск и воспроизведение

Проверено на **Python 3.13**, зависимости зафиксированы в `requirements.txt`.
Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Для просмотра достаточно открыть выполненный notebook на GitHub или локально.
Обновить все модельные таблицы и графики по сохранённым агрегатам без данных и весов:

```sh
python scripts/execute_notebook.py --section reports
```

Это режим по умолчанию. EDA-выводы сохраняются; исходный test не читается,
модели не обучаются. Проверяются контрольные суммы опубликованных свидетельств.
Это проверка отчёта; полная проверка локальных весов выполняется обучающими скриптами.

Повторить EDA и весь notebook последовательно с готовыми модельными отчётами:

```sh
python scripts/prepare_data.py --download
python scripts/execute_notebook.py --section all
```

Полностью повторить обучение, подбор и оценку **с нуля в новой папке**:

```sh
python scripts/reproduce.py --output ../recsys-reproduction
```

Папка должна отсутствовать и находиться вне исходного репозитория. Скрипт копирует
код и сетки, скачивает данные, создаёт split, выполняет пять поисков последовательно,
заново фиксирует validation-настройки, переобучает пять моделей и открывает test после
завершения всех пяти fit. Результаты, веса и выполненный notebook будут в новой папке.
Исходные frozen-отчёты не меняются. Для неудачного частичного запуска используйте новую
папку после проверки ошибки: автоматического возобновления финальной оценки нет.
Времена исполнения и последние разряды чисел могут зависеть от BLAS/платформы.

EASE требует квадратичную память: только финальная матрица float64 занимает около
**2,08 GiB**. Нужен запас RAM сверх этого для факторизации, данных и оценивания;
практический ориентир — 16 GB RAM и ≥10 GB свободного диска. Полный пересчёт включает
47 validation-конфигураций, две диагностические ablation и пять финальных fit.

## Файлы и ограничения

`models/` — пять реализаций; `data_utils.py`, `evaluation.py` — общие данные и оценка;
`scripts/` — загрузка, подбор, финальная оценка и воспроизведение;
`configs/` — заранее заданные сетки и финальный lock;
`reports/` — аудит, протокол, агрегаты, bootstrap, кривые и рисунки;
`tests/` — проверки формул, градиентов, кандидатов, временных ограничений и запуска notebook.
В `reports/submission_manifest.json` зафиксированы контрольные суммы кода и агрегатов.
Файлы `data/`, окружение, кэш, веса и персональные выдачи не публикуются.

Ограничения интерпретации:

- Отзывы — наблюдаемые оценки, а не логи показов, покупок и полного отрицательного feedback.
- Исходный и восстановленный 5-core используют когорту за весь период; это ограничивает
  строгость исторического моделирования, хотя обучение и признаки строятся по fit.
- Метаданные — снимок карточек при сборе. Для бренда и категорий предполагается
  стабильность; **историческая доступность не доказана**. Цены, sales rank, тексты
  будущих отзывов и related-item ссылки не используются. Название и описание — только EDA.
- Warm-start оценка исключает cold-start; горизонты validation/test различаются.
- Бюджеты подбора ограничены, обучение проверено с одним seed; результаты не являются
  доказательством предельных возможностей моделей или online A/B-эффекта.
